# git-local-review

ブラウザで動作するローカル diff レビューツールです。サーバー不要・ビルド不要のシングル HTML ファイルで提供されます。

🌐 GitHub Pages: https://toshi0907.github.io/git-local-review/

## 特徴

- **シングルファイル** — `index.html` をブラウザで開くだけで動作（サーバー・ビルド不要）
- **オフライン動作** — 外部サーバーへの通信は一切なし。highlight.js を含むすべての依存ライブラリをインライン同梱済み
- **差分の表示** — `git diff` / `git show` で生成されたユニファイド diff を貼り付けてレビュー
- **シンタックスハイライト** — ファイル拡張子を元に言語を自動検出し、差分行をハンク単位でハイライト表示（highlight.js v11.9.0 使用）
- **ハンクごとのレビュー管理** — ハンク単位で「レビュー済み」チェックが可能
- **進捗カウンター** — ファイルごと・全体の `n / m hunk` 進捗をリアルタイム表示
- **状態の永続化** — レビュー状態は `localStorage` に保存され、ページを再読み込みしても復元
- **最終アップロードファイルの保存** — 各プロジェクトについて最後に読み込んだ diff ファイルの内容も `localStorage` に保存され、ページ再読み込みやプロジェクト切り替え時に自動で再表示される
- **ファイルの再読み込み**（File System Access API 対応ブラウザのみ） — 一度開いた diff ファイルの参照を覚えておき、ファイル選択ダイアログを開き直さずに「🔃 再読み込み」ボタン一つでディスク上の最新内容を再取得できる
- **プロジェクト管理** — サイドバーでプロジェクトの切り替え・リセット・削除が可能
- **エクスポート / インポート** — プロジェクト一覧とレビュー状態を JSON ファイルとして保存・復元可能
- **文字コード対応** — UTF-8 に加えて Shift_JIS・EUC-JP の diff ファイルをバイト列から自動判定して読み込み。判定を誤った場合はプロジェクトごとに文字コードを指定して読み込み直せる
- **複数ファイルの一括アップロード** — ファイル選択ダイアログで複数の diff ファイルをまとめて選択すると、1 ファイルずつ順番に読み込まれ、それぞれ別プロジェクトとして追加される。同名の既存プロジェクトがあった場合は確認なしで新規プロジェクトとして追加し、完了後にまとめて通知される

## 使い方

1. このリポジトリをクローンまたは `index.html` をダウンロードする
2. `index.html` をブラウザで開く
3. `git diff` や `git show` の出力を `.diff` ファイルとして保存する
4. 「diff ファイルを読み込む」ボタンからファイルを選択してロード
5. 各ハンクの「レビュー済み」チェックボックスをオンにしてレビューを進める

```bash
# diff ファイルの生成例
git diff HEAD~1 > review.diff
git diff main..feature-branch > feature.diff
git show abc1234 > commit.diff
```

## シンタックスハイライト

ファイル拡張子から言語を自動検出し、diff の各行をハンク単位でハイライト表示します。拡張子が不明な場合はプレーンテキストとして表示されます。

**対応言語:** C++, C, JavaScript, TypeScript, Python, Ruby, Go, Rust, Java, C#, HTML, CSS, Bash, JSON, XML, YAML, Markdown, SQL, Kotlin, Swift, PHP, Scala

> highlight.js はファイル内にインライン同梱されており、外部 CDN への通信は発生しません。

## 文字コード対応

diff ファイルを読み込む際、ファイルのバイト列から文字コードを自動判定します。

- 有効な UTF-8 であれば UTF-8 として扱う
- そうでない場合は Shift_JIS と EUC-JP のバイトパターンをスコアリングし、より妥当性の高い方を採用する

自動判定の結果が誤っている場合は、以下の方法で文字コードを指定できます。

- サイドバーの「文字コード」セレクタで、次に読み込むファイルの文字コードを `UTF-8` / `Shift_JIS` / `EUC-JP` から明示的に指定
- 各プロジェクト項目の「文字コード」セレクタで、そのプロジェクトの文字コードをあとから変更（`📂 Diffファイルを開く` で開いた際に File System Access API のファイル参照が保存されている場合は、変更後すぐにディスクから再読み込みされる）

## プロジェクト ID

同じファイル名を同じ日に複数回ロードする場合、モーダルで既存プロジェクトに上書きするか新規作成するかを選択できます。

プロジェクト ID は以下の形式で自動生成されます：

```
sample.diff__proj_20260723_001
```

## データの保存先

レビュー状態はブラウザの `localStorage` に以下の構造で保存されます：

```json
{
  "projectId": {
    "filePath": {
      "hunkHash": true
    }
  }
}
```

ハンクの同一性は diff の内容行（`@@` ヘッダを除く）の SHA-256 ハッシュで判定されるため、行番号がずれても同じ内容のハンクは「レビュー済み」状態が引き継がれます。

また、各プロジェクトについて最後に読み込んだ diff ファイルの内容そのものも `localStorage`（プロジェクト ID をキーとした別の領域）に保存されます。これにより、ページを再読み込みしたりサイドバーで別のプロジェクトから戻ってきたりしても、diff ファイルを再度選択することなく表示とレビュー状態が復元されます。ストレージの空き容量が不足している場合は保存に失敗する旨のアラートが表示され、その場合は次回開いたときに手動での再読み込みが必要になります。

## ファイルの再読み込み（File System Access API）

Chrome / Edge など [File System Access API](https://developer.mozilla.org/ja/docs/Web/API/File_System_API) に対応したブラウザでは、「📂 Diffファイルを開く」でファイルを選ぶと、そのファイルへの参照（`FileSystemFileHandle`）がブラウザの IndexedDB に保存されます。

以後、同じ diff ファイルに更新（`git diff` の再生成など）があった場合も、サイドバーのプロジェクト項目に表示される「🔃 再読み込み」ボタンを押すだけで、ファイル選択ダイアログを開き直すことなくディスク上の最新内容を再読み込みできます。レビュー済みチェックは内容が同じハンクについてはそのまま引き継がれます。

ファイルの参照が保存されていないプロジェクト（インポートしたプロジェクトや、非対応ブラウザで作成したプロジェクトなど）や、参照先のファイルが移動・削除された場合は、「🔃 再読み込み」ボタンは表示されないか、再読み込みに失敗した旨のメッセージが表示されます。その場合は「📂 Diffファイルを開く」から選び直してください。

File System Access API 非対応のブラウザ（Firefox・Safari など）では、従来どおりファイル選択ダイアログ（`<input type="file">`）でファイルを読み込みます。

## エクスポート / インポート

サイドバーの「💾 エクスポート」ボタンから、保存されている全プロジェクトとレビュー状態（`localStorage` の内容）を JSON ファイルとしてダウンロードできます。

「📥 インポート」ボタンでエクスポート済みの JSON ファイルを選択すると、その内容がブラウザに復元されます。同じ ID のプロジェクトが既に存在する場合は上書きされ、それ以外の既存プロジェクトはそのまま保持されます。

> 各プロジェクトの最終アップロードファイルの内容はローカルの `localStorage` には保存されますが、エクスポート/インポートの対象には含まれません（ファイルサイズがエクスポートJSONを肥大化させるのを避けるため）。他のブラウザ・端末にインポートした場合や、保存されたファイル内容が失われた場合は、元の diff ファイルを再度読み込んでください。

## 動作環境

モダンブラウザであれば動作します。SHA-256 ハッシュには Web Crypto API (`crypto.subtle`) を使用し、利用できない場合は非暗号学的ハッシュにフォールバックします。
