# git-local-review

ブラウザで動作するローカル diff レビューツールです。サーバー不要・ビルド不要のシングル HTML ファイルで提供されます。

🌐 GitHub Pages: https://toshi0907.github.io/git-local-review/

## 特徴

- **シングルファイル / オフライン動作** — `index.html` を開くだけで動作し、highlight.js を含む依存ライブラリはすべてインライン同梱。外部通信は一切なし
- **diff の表示とレビュー** — `git diff` / `git show` のユニファイド diff を貼り付け、シンタックスハイライト付きでハンク単位に「承認 / 要修正 / 保留」の3段階でレビュー状態を記録できる
- **Unified / 左右表示の切り替え** — 表示モードは `localStorage` に保存され次回も保持
- **キーボードショートカット** — `j` / `k` でハンク移動、`Space` でレビュー状態を循環、`1`/`2`/`3` で直接指定
- **進捗管理** — 表示フィルタ（未レビューのみ / 要修正のみ）、ファイルごと・全体の進捗カウンター（要修正・保留の内訳表示付き）
- **状態の永続化** — レビュー状態・最終読み込みファイルは `localStorage` に保存され、再読み込みしても復元
- **レビューメモ** — トップバーの📝アイコンから開くスライドパネルで、ファイルやハンクに紐付かないチェックリスト形式のメモをプロジェクトごとに残せる（複数行入力・長文の折り返し表示に対応）
- **File System Access API 連携**（対応ブラウザのみ） — diff ファイルの再読み込み、既定フォルダの指定、設定の自動保存に対応
- **プロジェクト管理** — 複数プロジェクトの切り替え・並び替え・削除、JSON でのエクスポート / インポート
- **文字コード自動判定** — UTF-8 / Shift_JIS / EUC-JP を自動判定して読み込み
- **複数ファイル一括読み込み / ドラッグ&ドロップ** — 複数 diff ファイルをまとめて選択・ドロップして個別プロジェクトとして追加
- **キーワードハイライト（カテゴリ別）** — トップバーの🎨アイコンから開く画面で、キーワード（`TODO` / `SECURITY` など）をカテゴリごとに登録し、カテゴリごとに背景色を指定して diff 中でハイライト
- **キーワード行抽出** — トップバーの🔎アイコンから開く画面で、キーワードハイライトとは別に登録したキーワードごとに、差分中の追加/削除行（`+`/`-` で始まる行のみ）を一覧抽出。キーワードは全体設定／プロジェクト毎のいずれかを選んで保存可能

## 使い方

1. このリポジトリをクローンするか `index.html` をダウンロードする
2. `index.html` をブラウザで開く
3. `git diff` や `git show` の出力を `.diff` ファイルとして保存する
4. 「diff ファイルを読み込む」ボタンから選択、またはウィンドウにドラッグ&ドロップして読み込む
5. 各ハンクのヘッダーにある「✓ 承認」「✎ 要修正」「⏸ 保留」ボタンで状態を記録しながらレビューを進める

```bash
# diff ファイルの生成例
git diff HEAD~1 > review.diff
git diff main..feature-branch > feature.diff
git show abc1234 > commit.diff
```

## 機能詳細

### シンタックスハイライト

ファイル拡張子から言語を自動検出し、diff の各行をハンク単位でハイライト表示します（highlight.js v11.9.0、インライン同梱で外部 CDN 通信なし）。拡張子が不明な場合はプレーンテキスト表示になります。

**対応言語:** C++, C, JavaScript, TypeScript, Python, Ruby, Go, Rust, Java, C#, HTML, CSS, Bash, JSON, XML, YAML, Markdown, SQL, Kotlin, Swift, PHP, Scala

### キーボードショートカット

| キー | 動作 |
| --- | --- |
| `j` | 次のハンクへフォーカスを移動 |
| `k` | 前のハンクへフォーカスを移動 |
| `Space` | フォーカス中のハンクのレビュー状態を 未レビュー → 承認 → 要修正 → 保留 → 未レビュー… の順で循環 |
| `1` | フォーカス中のハンクを「承認」に設定（もう一度押すと未レビューに戻す） |
| `2` | フォーカス中のハンクを「要修正」に設定（もう一度押すと未レビューに戻す） |
| `3` | フォーカス中のハンクを「保留」に設定（もう一度押すと未レビューに戻す） |

ハンク領域をマウスクリックしてもそのハンクをフォーカス状態にできます。クリックでハンクを選び `Space` や数字キーでレビュー状態を切り替える、という操作にも対応しています。

フォーム入力中やモーダル表示中はショートカットが無効になります。

### 文字コード対応

diff ファイルのバイト列から文字コードを自動判定します（有効な UTF-8 はそのまま採用、それ以外は Shift_JIS / EUC-JP をスコアリングして採用）。判定を誤った場合は、サイドバーまたは各プロジェクト項目の「文字コード」セレクタから `UTF-8` / `Shift_JIS` / `EUC-JP` を明示的に指定できます。

### File System Access API 連携（Chrome / Edge など対応ブラウザのみ）

「📂 Diffファイルを開く」で選んだファイルの参照（`FileSystemFileHandle`）を IndexedDB に保存することで、以下の機能が使えます。非対応ブラウザ（Firefox・Safari など）ではこれらの UI 自体が非表示になり、従来どおり `<input type="file">` でファイルを読み込みます。

- **再読み込み** — diff ファイルが更新された場合、サイドバーの「🔃 再読み込み」ボタン一つでファイル選択ダイアログを開かずに最新内容を再取得。内容が同じハンクのレビュー状態は引き継がれる
- **既定のフォルダ** — サイドバーでフォルダを一つ選んでおくと、「📂 Diffファイルを開く」のダイアログが毎回そのフォルダから開く
- **設定の自動保存** — 保存先フォルダを指定すると、diff ファイルの読み込み・レビュー状態の変化・プロジェクトの削除のたびに、そのフォルダ内の `git-local-review-settings.json` へプロジェクト一覧とレビュー状態が自動で書き込まれる（変更が続く間は少し待ってからまとめて1回保存）。「💾 設定保存」ボタンでいつでも即座に保存することもできる。次回ページを開いたときにファイルがあれば自動で読み込まれる（同じ ID のプロジェクトは上書き、それ以外は保持）
- **他環境での更新検知** — 保存先フォルダの `git-local-review-settings.json` が別のブラウザ/環境から更新されていないか、一定間隔（1分ごと）と自動保存の直前に確認する。更新が検知された場合、自動保存はそのデータを上書きしないようスキップされ、サイドバーに「保存先フォルダのデータが他の環境で更新されています」という通知と「読み込む」ボタンが表示される。読み込みは自動では行われず、ボタンから手動で行う

参照先のファイル・フォルダが移動/削除された場合は、該当機能が失敗した旨のメッセージが表示されるので、その場合は選び直してください。

### プロジェクト ID

同じファイル名を同じ日に複数回ロードする場合、モーダルで既存プロジェクトへの上書きか新規作成かを選択できます。プロジェクト ID は `sample.diff__proj_20260723_001` の形式で自動生成されます。

### ブラウザに保存される情報一覧

このツールはサーバーを持たず、外部通信も一切行いません。すべてのデータはブラウザの `localStorage` と `IndexedDB` にのみ保存されます。

#### localStorage

| キー | 内容 |
| --- | --- |
| `gitLocalReview_projects` | プロジェクト一覧（ID・ファイル名・作成日時・更新日時・文字コード設定など） |
| `gitLocalReview_reviews` | プロジェクトごとのハンクのレビュー状態（後述の構造） |
| `gitLocalReview_memos` | プロジェクトごとのレビューメモ（チェックリスト、後述の構造） |
| `gitLocalReview_files` | 各プロジェクトの最終読み込みファイルの内容（プロジェクト ID をキーに保存） |
| `gitLocalReview_currentProject` | 直前に開いていたプロジェクトの ID |
| `gitLocalReview_viewMode` | diff の表示モード（`unified` / `split`） |
| `gitLocalReview_reviewFilter` | ハンク表示フィルタ（`all` / `unreviewed` / `needs_changes`） |
| `gitLocalReview_projectSort` | プロジェクト一覧の並び順 |
| `gitLocalReview_keywords` | キーワードハイライトのカテゴリ配列（`{ id, keywords, color }[]` の JSON） |
| `gitLocalReview_projectKeywords` | プロジェクト毎のキーワードハイライトカテゴリ（`{ [projectId]: category[] }` の JSON） |
| `gitLocalReview_extractKeywords` | キーワード行抽出の全体設定キーワード配列（`{ id, keyword, fileFilter }[]` の JSON、キーワードハイライトとは別機能） |
| `gitLocalReview_projectExtractKeywords` | プロジェクト毎のキーワード行抽出キーワード（`{ [projectId]: entry[] }` の JSON） |

`gitLocalReview_reviews` は以下の構造で保存されます。値は `"approved"`（承認）/ `"needs_changes"`（要修正）/ `"on_hold"`（保留）のいずれかで、キー自体が存在しない場合は未レビューです。

```json
{
  "projectId": {
    "filePath": {
      "hunkHash": "needs_changes"
    }
  }
}
```

ハンクの同一性は diff の内容行（`@@` ヘッダを除く）の SHA-256 ハッシュで判定されるため、行番号がずれても同じ内容のハンクはレビュー状態が引き継がれます。

`gitLocalReview_memos` は以下の構造で保存されます。ファイル・ハンクとの紐付けはなく、プロジェクト単位のチェックリストです。

```json
{
  "projectId": [
    { "id": "memo_...", "text": "メモの内容", "done": false, "createdAt": 0, "updatedAt": 0 }
  ]
}
```

各プロジェクトの最終読み込みファイルの内容（`gitLocalReview_files`）により、再読み込みやプロジェクト切り替え後も表示が復元されます。ストレージの空き容量が不足している場合は保存失敗のアラートが表示され、次回開いたときに手動での再読み込みが必要になります。

#### IndexedDB（File System Access API 対応ブラウザのみ）

`FileSystemFileHandle` / `FileSystemDirectoryHandle` は JSON 化できないオブジェクトのため、`gitLocalReview_handles` という名前の IndexedDB データベースに保存されます。

| オブジェクトストア | キー | 内容 |
| --- | --- | --- |
| `fileHandles` | プロジェクト ID | 「🔃 再読み込み」用に記憶した diff ファイルの参照 |
| `folderHandles` | `defaultOpenFolder` | 「📂 Diffファイルを開く」の既定フォルダの参照 |
| `folderHandles` | `settingsFolder` | 「💾 設定保存」の自動保存先フォルダの参照 |

保存されるのはファイル・フォルダへの「参照」のみで、内容そのものは含まれません。参照先が移動・削除された場合は再選択が必要です。

### エクスポート / インポート

「💾 エクスポート」で全プロジェクト・レビュー状態・レビューメモを JSON ファイルとしてダウンロードできます。「📥 インポート」で復元する際、同じ ID のプロジェクトは上書きされ、それ以外の既存プロジェクトは保持されます。

> 各プロジェクトの最終読み込みファイルの内容は `localStorage` には保存されますが、ファイルサイズの肥大化を避けるためエクスポート/インポートの対象には含まれません。他のブラウザ・端末に復元した場合は、元の diff ファイルを再度読み込んでください。

## 動作環境

モダンブラウザであれば動作します。SHA-256 ハッシュには Web Crypto API（`crypto.subtle`）を使用し、利用できない場合は非暗号学的ハッシュにフォールバックします。
